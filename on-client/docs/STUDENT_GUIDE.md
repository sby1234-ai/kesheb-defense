# 학생 설명서 · 보안 Agent (케셰브 방어전 13~21단계)

이 문서는 학생이 새로 만든 설명서입니다. 제공 문서(`README.md`, `docs/` 의 다른 파일)는 고치지 않았습니다.
시작 틀 버전: 0.2.14 (`package.json`). 학생이 고친 코드 파일은 `student/extension.mjs` 하나입니다.

> 열쇠·비밀번호·토큰 같은 비밀 값은 이 문서와 코드, 커밋 어디에도 넣지 않습니다.

---

## 1. 설치·실행 순서

준비물: Windows PowerShell, Node.js 24.19.0 (외부 npm 의존성 없음 → `npm install` 필요 없음), Git.

새 PowerShell 창에서 순서대로 실행합니다.

```powershell
# 1) 저장소 받기 (이미 받은 폴더가 있으면 건너뜀)
git clone https://github.com/sby1234-ai/kesheb-defense.git
cd kesheb-defense\on-client

# 2) Node.js 버전 확인 → v24.19.0 이 나와야 합니다
node --version

# 3) 학생 코드 문법 확인 (아무 출력 없이 끝나면 정상)
node --check student/extension.mjs

# 4) 앱 켜기 (제공 실행 도구: Node 버전·포트를 먼저 확인합니다)
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

5) PC 브라우저에서 **http://127.0.0.1:5189** 를 엽니다.

| 하고 싶은 것 | 명령 | 비고 |
|---|---|---|
| 앱 켜기(다른 방법) | `npm.cmd start` | `node src/server.mjs` 와 같습니다. PowerShell 이 `npm` 스크립트 실행을 막으면 `npm.cmd` 로 씁니다. |
| 예제 자료로 화면만 보기 | `npm.cmd run demo` | 예제 자료입니다. 실제 연결이나 성취가 아닙니다. |
| 문법만 확인 | `npm.cmd run check` | `node --check student/extension.mjs` 와 같습니다. |
| 끄기 | 앱을 켠 PowerShell 창에서 `Ctrl+C` | 브라우저 주소가 더 열리지 않으면 꺼진 것입니다. |
| 다시 켜기 | 4) 의 명령을 같은 폴더에서 다시 실행 | |
| 포트 5189 충돌 | 4) 명령 끝에 ` -Port 5190` | 브라우저 주소도 `http://127.0.0.1:5190` 으로 엽니다. |

명령은 반드시 `on-client` 폴더 안에서 실행합니다. 다른 곳에서 실행하면 `앱 폴더가 아닙니다` 메시지가 나옵니다.

## 2. 구성도

```
┌──────────────────────────────────────────┐
│ ① 브라우저 (학생 PC)                       │
│   주소: http://127.0.0.1:5189             │
│   제공 화면: public/index.html, public/app.js │
│   학생 화면: student/extension.mjs          │
└───────────────┬──────────────────────────┘
                │ HTTP (같은 PC, 127.0.0.1:5189)
                ▼
┌──────────────────────────────────────────┐
│ ② 앱 서버 (Node.js 24.19.0)               │
│   파일: src/server.mjs                     │
│   실행: tools/start-alekov.ps1 / npm start │
└───────┬───────────────────────┬──────────┘
        │ 접속 판정·기록·조치     │ AI 연결 점검·사건 설명
        ▼                       ▼
┌────────────────────────┐  ┌────────────────────────┐
│ ③ 기존 접속·XDR 서버     │  │ ④ CLCO 수업용 AI        │
│   (회사 시스템, SDP)     │  │   파일: vendor/clco-http.mjs │
│   파일: src/engine/      │  │   앱 안 연결: src/ai/service.mjs │
│        sdp-host.mjs      │  │                        │
│   연결 관리:             │  │                        │
│   src/connection/manager.mjs │                        │
└────────────────────────┘  └────────────────────────┘
```

- 브라우저는 ②앱 서버하고만 통신합니다. ③·④ 에 직접 연결하지 않고, 주소나 열쇠를 입력하는 칸도 없습니다.
- 학생 코드(`student/extension.mjs`)는 서버가 넘겨준 입력을 받아 화면(DOM)만 만듭니다. 요청을 보내거나 조치를 실행하지 않습니다.
- 상자별 확인 상태: ①·② 는 이 PC에서 앱을 켜고 주소가 열리는 것으로 확인합니다. ③ 기본 실행은 실제 회사 시스템에 연결되지 않은 상태(`연결 없음`)이며 실제 응답은 **확인 안 됨**입니다. ④ 는 계정·앱 권한 준비에 따라 달라지며 실제 설명 응답은 **확인 안 됨**입니다(5장 UNV 참고).

## 3. 제공 코드와 내가 만든 부분

기준: `.on-starter-manifest.json` 의 `sourceHashes` 목록.

| 구분 | 파일 | 누가 |
|---|---|---|
| 제공 | `public/` (index.html, app.js, ai-connect.mjs, vulnerabilities-view.mjs, style.css, assets) | 시작 틀 · 고치지 않음 |
| 제공 | `src/` (server.mjs, engine/, connection/, ai/, actions/, vulnerabilities/, learner-support/) | 시작 틀 · 고치지 않음 |
| 제공 | `tools/*.ps1`, `vendor/`, `docs/` 의 기존 문서, `README.md`, `package.json`, `.env.example` | 시작 틀 · 고치지 않음 |
| 학생 | `student/extension.mjs` | **학생 구현** (13~20단계) |
| 학생 | `student/engine-adapter.mjs` | 학생 영역이지만 이번 과정에서 고치지 않음 |
| 학생 | `docs/STUDENT_GUIDE.md` (이 문서) | **학생 작성** (21단계) |

### 내가 구현한 함수 (`student/extension.mjs` → `createStudentView()`)

모든 함수는 `document.createElement` + `textContent` 로 매번 새 DOM 을 만들어 돌려줍니다. 그래서 새 상태가 오면 이전 결과가 화면에 남지 않고, `innerHTML` 을 쓰지 않아 받은 글자가 코드로 실행되지 않습니다.

| 단계 | 함수 | 보여 주는 것 |
|---|---|---|
| 13 | `renderIdentity` | 내 로그인 정보, 기기 목록, 세션 목록. 정상이 아닌 값(미충족·만료·철회·알 수 없음)은 `⚠ 주의` 글자로 구분하고, 불러오기 실패와 "없음"을 따로 보여 줍니다. |
| 14 | `renderDecision` | 업무 앱 접속 판정(허용·거부·추가 확인·확인 불가). 요청 실패와 목록에 없는 값은 허용으로 보이지 않게 합니다. |
| 15 | `renderEvents` | 내 접속 기록(access)과 저장된 XDR 경보(xdr) 최근 40건, 상세 근거. 빈 목록과 불러오기 실패를 구분합니다. 조치 버튼은 요청을 보내지 않는 비활성 `미지원` 표시입니다. |
| 16 | `renderStatus` | 알림·기기·세션·진단 상태를 한 화면에. "현재 연결 없음"과 "불러오기 실패"를 구분합니다. |
| 17 | `renderAiConnection` | 앱 안 AI 연결 점검 결과(점검 전·점검 중·실패 원인별 안내·성공). 연결 점검 성공을 사건 설명 성공으로 쓰지 않습니다. |
| 18 | `renderExplanation` | 고른 기록의 AI 설명. 인용한 근거 ID 가 그 기록의 근거에 없거나 이미 실행됐다고 오면 거부하고, 근거·규칙·모르는 상태·제안을 나눠 보여 줍니다. |
| 19 | `renderAction` | 조치 요청의 상태(준비·실행 중·대기·성공·거부·실패·결과 불명·만료). 접수(ACK)는 효과가 아니며, `effectApplied === true` 일 때만 성공으로 표시합니다. 버튼은 만들지 않습니다. |
| 20 | `renderVulnerabilities` | 잠금 파일 기준 라이브러리 이름@정확한 버전과 취약점 조회 상태. 조회 실패·미확인·미설정은 "취약점 없음이 아님"으로 표시합니다. |

## 4. 실패별 해결 안내

화면에 실제로 나오는 문구(`student/extension.mjs` 의 글자 그대로)입니다.

| 화면 문구 | 원인 | 확인할 것 |
|---|---|---|
| `연결 없음 (disconnected)` | 앱 서버가 실제 회사 시스템(③)에 연결되지 않은 기본 실행 상태 | 정상적인 기본 상태입니다. 실제 연결은 담당자 안내(`docs/SDP_HOST_CONNECTION.md`)가 있을 때만 합니다. |
| `예제 자료 (demo)` | `npm run demo` 로 켬 | 실제 자료가 아닙니다. 실제 확인은 `start-alekov.ps1` 또는 `npm start` 로 다시 켭니다. |
| `기기 목록 연결 실패: …` / `세션 목록 연결 실패: …` | 서버가 그 목록을 가져오지 못함 | 앱 서버 창의 오류 메시지를 확인하고 화면을 다시 불러옵니다. |
| `현재 연결 없음: 지금 검증된 세션이 없습니다. (불러오기는 성공했습니다)` | 불러오기는 됐지만 활성 세션이 0개 | 오류가 아닙니다. 로그인·계정 연결 상태를 확인합니다. |
| `요청 실패: … ` + `이것은 접근 거부 판정이 아니며…` | 접속 판정 요청이 서버에서 실패 | 거부가 아닙니다. 앱 서버가 켜져 있는지 확인하고 앱 버튼을 직접 다시 누릅니다. |
| `확인 불가(unknown): 판정 결과를 확인할 수 없습니다. 허용되지 않은 상태로 봅니다.` | 판정 응답이 없거나 형식이 다름 | 허용이 아닙니다. 다시 요청합니다. |
| `확인 불가(CONTRACT_MISMATCH)…` / `확인 불가(ENGINE_RESULT_UNVERIFIED)…` | 받은 기록의 형식을 확인할 수 없음 | 빈 목록이 아닙니다. 다시 불러오기를 누르고, 계속되면 담당자에게 알립니다. |
| `기록을 불러오지 못했습니다: …` | 기록 조회 실패 | 빈 목록이 아니라 실패입니다. 다시 불러오기를 직접 누릅니다. |
| `AI 연결 점검 실패 · 권한 준비 중·확인 불가` | `ON_AI_PROVISIONING_PENDING` 등: 계정·앱 권한 미준비 | 학생 잘못이 아닙니다. 담당자에게 계정 연결·앱 권한 확인을 요청합니다. |
| `AI 연결 점검 실패 · 인증 실패` | `WB_CLCO_AUTH_REQUIRED` | 계정 연결을 다시 확인합니다. 열쇠를 복사해 붙이지 않습니다. |
| `AI 연결 점검 실패 · 접근 제한` / `사용량·이용 한도` / `이용 시간 아님` | `WB_CLCO_ACCESS_BLOCKED` / `…BUDGET_EXHAUSTED`·`…LIMIT_REACHED` / `WB_CLCO_SESSION_CLOSED` | 담당자에게 권한·한도를 확인하거나 이용 시간을 확인합니다. |
| `AI 연결 점검 실패 · 요청 제한·시간 초과·네트워크` | 시간 초과·네트워크 오류 | 잠시 뒤 「현재 API 연결 점검」을 직접 다시 누릅니다(자동 재시도 없음). |
| `AI 연결 점검 실패 · 쓸 수 있는 모델 없음` | `ON_AI_MODEL_LIST_EMPTY` / `MODEL_NOT_CONFIGURED` | 담당자에게 모델 허용 설정을 요청합니다. |
| `AI 설명 실패` | 사건 설명 요청 실패 | 기록은 그대로입니다. 오류 코드를 확인하고 다시 요청합니다. |
| `조치 상태: 결과 불명(unknown)…` / `결과 불명(succeeded 로 왔으나 effectApplied 가 true 가 아님)…` | 조치 효과가 확인되지 않음 | 성공으로 보지 않습니다. 원천 결과를 다시 조회합니다. |
| `조치 상태: 실패(failed).` | 원천이 조치 실패를 알림 | 표시된 사유를 확인합니다. |
| `확인 불가: 조회 결과를 확인할 수 없습니다. "취약점 없음"이 아닙니다.` | 취약점 조회 실패·미설정 | 취약점이 없다는 뜻이 아닙니다. 조회를 다시 실행합니다. |

실행 도구 자체의 오류(`Node.js 가 없습니다`, `포트 5189 를 다른 프로그램이 쓰고 있습니다`, `앱 폴더가 아닙니다`)는 1장 표와 제공 문서 `docs/STUDENT_LAUNCH_GUIDE.md` 4장을 봅니다.

## 5. 지원 범위

### 확인한 것

- `node --check student/extension.mjs` 문법 통과.
- 13~20단계 화면 함수 구현과 ALEPH 제출·판정 통과(서버의 AI 가 코드 원문을 읽어 판정하며, 코드를 실행한 인증은 아님).
- 각 함수에 가짜 입력을 넣어 상태별 문구가 나오는지 학생이 직접 확인(DOM 대역 사용).
- 앱은 기본 실행에서 실제 회사 시스템에 연결되지 않은 상태로 뜹니다.

### 기다림(UNV) · 아직 실제로 확인하지 못한 것

- 실제 회사 시스템(③ SDP·XDR) 연결과 실제 로그인·인증 결과.
- 실제 조치 실행 연결(19단계): 화면은 상태 표시만 하며 실제 원천 집행은 확인하지 않았습니다.
- CLCO 수업용 AI(④)로 실제 사건 설명을 받은 결과: 연결 점검 화면만 구현·확인했습니다.
- OSV 취약점 조회의 실제 결과(20단계): 화면은 받은 결과를 표시만 하며, 실제 조회 결과는 확인하지 않았습니다.
- 22단계 새 환경 재현과 21·22단계 공식 접수 연결.

따라서 이 버전은 **검증 중인 버전**이며 v1.0 이 아닙니다.
